# 첫 구현: 로컬 감각·이동 테스트

## 상태

Unity 6000.6.4f1에서 C# 컴파일, LocalTest와 NetworkTest 장면 생성, Windows 개발 빌드가 성공했다. 동일 PC에서 호스트와 클라이언트 3개를 실제 실행해 역할 배정, 원격 입력·이동 동기화와 공 물리 동기화를 확인했다. 화면과 실제 사람 4명의 플레이, 다른 PC·외부 네트워크 검증은 아직 하지 못했다.

엔진: 사용자 승인으로 Unity 선택. 사용자가 설치한 Unity 6.6, 정확한 버전 6000.6.4f1로 고정했다.

## 실행 준비

1. Unity Hub에서 Unity 6000.6.4f1 설치 및 개인 계정 라이선스 활성화. 현재 PC에서는 완료됨.
2. 저장소 루트를 프로젝트로 추가. Assets, Packages, ProjectSettings 폴더가 있는 위치다.
3. `Assets/NightToyStore/Scenes/LocalTest.unity` 열기. 장면은 이미 생성됨. 재생성할 때는 `Night Toy Store > Create Local Test Scene` 실행.
4. Play를 눌러 테스트. 입력 오류가 있으면 Player Settings의 Active Input Handling을 Input Manager 또는 Both로 설정하고 재시작.

## 현재 코드 범위

### 네트워크 테스트

- 장면: `Assets/NightToyStore/Scenes/NetworkTest.unity`.
- 최신 실행 파일: `Builds/NetworkTest-06/NightToyStore.exe`. 이전 파일은 `Builds/NetworkTest`와 `Builds/NetworkTest-02`에 남아 있다. 빌드 산출물은 Git에 올리지 않는다.
- Host 또는 Join 선택. 같은 PC는 주소 `127.0.0.1`, LAN은 호스트의 LAN IP. UDP 포트 7777. 외부 인터넷 접속·스팀 초대는 아직 지원하지 않는다.
- 최대 4명. 접속 순서대로 라디오, 할머니, 토끼, 공을 임시 배정한다. 출시용 역할 선택 규칙이 아니다.
- 테스트 중 1 라디오 / 2 할머니 / 3 토끼 / 4 공으로 변경 가능. 다른 플레이어가 가진 역할을 선택하면 서로 교환한다. 두 창으로 공과 이동 가능한 역할을 시험할 수 있다. 역할 선택·교환은 테스트 편의 기능이다.
- 역할 변경은 서버에서 처리하고 카메라 높이, 외형, 물리·이동 상태를 갱신한다. 스태미나는 테스트용으로 초기화한다.
- 바닥·벽·캐릭터는 Resources에 포함한 명시적인 테스트용 셰이더를 사용한다. 실행 중 생성한 기본 재질이 빌드에서 핑크색으로 표시되는 문제를 수정했다. 테스트용 셰이더는 최종 공포 조명 시스템이 아니다.
- 다른 캐릭터의 역할과 거리를 화면에 표시하여 위치 확인을 돕는다. 최종 게임 UI가 아닌 디버그 표시다.
- 이동·스태미나·공 물리는 서버에서 계산하고 위치는 클라이언트에 동기화한다.
- WASD 이동, Shift 달리기. 공에 몸으로 부딪혀 밀어 굴린다. E 굴리기 기능은 사용자 요청으로 제거했다. 들기·던지기 없음.
- 공은 벽에 부딪힌 법선 방향 속도에 비례하여 반동한다. 현재 테스트 탄성계수는 0.8이며 최종 값은 미정. 연속 충돌 검출을 사용해 빠른 공의 벽 통과를 방지한다.
- 접속 시 활성 창의 마우스를 자동으로 잡아 시선을 회전한다. Esc로 해제하고 창 안을 클릭해 다시 잡는다. 창 전환 후에는 활성 창만 입력을 처리한다.
- 이동·몸 밀기는 일정한 물리 업데이트 간격에서 계산한다. 높은 프레임에서 작은 이동을 무시하던 CharacterController 최소 이동거리도 0으로 설정했다.
- 공은 자력 이동 불가, 카메라는 회전과 무관하게 다른 두 캐릭터 높이 유지. 외형의 실제 회전 연출은 미구현.
- 라디오 주파수 데이터와 할머니 검은 화면 시야도 포함. 네트워크 테스트에서는 실제 음성 전송·주파수 청취 제한·파동 시야를 구현했다.
- 현재 몸 밀기의 속도 배율과 마찰·탄성은 임시 테스트 값이다.

### 로컬 테스트

- 임시 방·선반을 실행 시 생성.
- 1~4 키로 역할 전환. WASD 이동, Shift 달리기, 마우스 시선, Esc 커서 해제.
- 토끼 > 라디오 > 할머니 이동속도, 스태미나 소모·회복.
- 공 역할은 자력 이동 불가, 토끼만 낮은 카메라.
- 할머니는 검은 화면, Space로 임시 시야 확인. 실제 파동·벽 너머 윤곽은 아직 미구현.
- 라디오의 랜덤 정답 변경과 휠 재조정 데이터. 음성 필터링은 아직 미구현.

모든 이동속도, 스태미나 수치, 주파수 범위·변경 간격·허용 오차와 시야 지속시간은 개발용 임시값이다. 승인된 최종 게임 규칙이 아니다. 디버그 주파수 정답 표시는 테스트 전용이다.

## 자동 검증

- Netcode for GameObjects 2.13.3. 2.7.0은 Unity 6.6 API와 호환되지 않아 교체했다. 3.1.0은 Unity 6.7용이므로 사용하지 않는다.
- Windows 개발 빌드 후 `tools/Verify-Network.ps1` 실행.
- 호스트 성공 표식과 클라이언트 3개 각각의 역할·수평 이동 복제 성공 표식을 확인한다. 공에는 서버의 테스트 전용 수평 충격을 가해 물리 복제를 검사한다.
- 2026-10-07 실행 결과: PASS. 테스트 로그의 예외·오류 표식 없음. LAN의 지연·패킷 손실과 화면 검증을 대신하지 않는다.
- 사용자 수동 확인: 같은 PC에서 첫 4개 창 접속, 5번째 접속 차단, 라디오·할머니·토끼·공 역할 배정 확인.
- 그래픽 수정 검증: 실제 D3D11 렌더링 이미지에서 바닥·벽·선반 확인, 핑크 오류 픽셀 0. 원격 캐릭터 라벨의 실제 화면 검증은 아직 별도 확인 필요.
- `tools/Verify-TwoRoles.ps1` PASS: 두 플레이어의 역할 변경·점유 역할 교환·카메라 높이 변경과 복제 확인.
- `tools/Verify-Physics.ps1` PASS: 실제 CharacterController 몸 접촉으로 공 밀기, 속도 2/6/14의 실제 벽 충돌에서 방향 반전과 탄성계수 0.8 확인, 카메라 회전·상하 제한 계산 확인. 실제 마우스 장치 입력·창 전환 감각은 사용자 확인이 필요하다.
- 물리·입력 변경 후 기존 4인 복제와 2인 역할 교환 테스트도 다시 PASS.
- 사용자가 새 버전의 몸 밀기·벽 반동·마우스 회전 수정이 정상 작동한다고 확인했다.

## 인게임 음성과 할머니 파동 (네트워크 장면 / 04 버전)

- 사용자 승인: 자동 음성 감지와 누르고 말하기를 모두 지원하고 설정에서 선택. 기본 테스트 모드는 V키를 누르는 방식.
- Esc로 커서를 풀고 Automatic voice / Hold V to talk 선택. 선택은 PC 설정에 저장된다. M으로 마이크 음소거, Change microphone으로 장치 전환.
- 토끼는 마이크 송신 불가. 서버도 토끼의 음성 패킷을 차단한다. 듣기는 가능하다.
- 일반 캐릭터는 거리 기반 음성. 라디오는 정답 주파수일 때 거리와 무관하게 듣고 틀리면 음성 차단.
- 할머니는 평소 검은 화면. Space 지팡이, 움직이는 플레이어 발소리, 말하는 플레이어 목소리가 발생한 위치에서 청록 파동이 퍼져 벽 너머 지형 윤곽도 드러난다. 다른 역할에는 파동이 보이지 않는다.
- 두 창 테스트: 한 창 2(할머니), 다른 창 4(공) 또는 1(라디오). 말하는 창에서 V를 누르고 말한다. 같은 PC의 마이크를 두 창이 사용하므로 듣는 창의 마이크는 M으로 끄고 헤드폰을 사용하면 확인하기 쉽다.
- 기술 범위: LAN용 16kHz 모노 PCM16, 20ms 패킷, 약 60ms 수신 버퍼. 압축 코덱·인터넷 음성 품질·패킷 손실 보정은 향후 구현. 서버는 실제 전달되는 음성의 크기로 파동을 생성한다. 녹음 파일을 저장하지 않는다.
- 파동 범위·속도·지속시간과 자동 감지 임계값은 개발용 임시 수치. 괴물 음원과 마더 반응은 괴물 구현 시 연결한다.
- 검증: Windows 빌드 성공. 실제 GPU 무음 검은 화면·지팡이·음성 파동 캡처, 핑크 오류 픽셀 0. 합성 음성 두 프로세스 통합 테스트 PASS: PCM 변환, 음성 전달, 목소리 파동, 토끼 차단, 지팡이 역할 제한. 실제 마이크 장치·사람 음성 청취는 사용자 확인 대기.
- 재검증: tools/Verify-Voice.ps1 (실제 마이크를 사용하지 않는 명시적 테스트).

## 05 버전 변경

최신 실행 파일은 Builds/NetworkTest-06/NightToyStore.exe.
공 시점 0.95m(토끼 0.65m, 할머니 1.5m), 지름 1.3m. 굴림과 무관한 안정적인 시선 유지. 눈·입 등 최종 모델 연출은 아직 임시 구체 외형이다.
할머니 Space 지팡이: 10초 재사용 제한과 대기시간 표시. 발걸음은 짧고 약한 근거리 윤곽만 표시한다.
Esc → Mic gain(입력 증폭), Voice volume(다른 플레이어 음량), Detection(낮을수록 작은 소리 자동 감지) 조절.
작은 마이크 테스트는 Mic gain 3~5배부터, V키를 눌러 말하며 level 수치 반응과 다른 창의 할머니 파동을 확인한다.
발걸음 파동은 횟수를 인위적으로 줄이는 대신 소리 이벤트마다 한 번 확산한다. 발걸음 2m·목소리 3m는 예시를 적용한 임시 테스트 값이며 거리 밖 소리는 파동으로도 보이지 않는다. 목소리는 발화 시작에 한 번, 잠시 멈췄다 다시 말하면 새 파동이 발생한다.

## 최신 06 버전

Builds/NetworkTest-06/NightToyStore.exe. 할머니 자신의 목소리도 파동 생성. 걷기 파동은 승인된 이동 3m 간격/범위 6m로 변경(예전 2m 범위 설명을 대체). 지팡이 10초 제한 유지.
네 캐릭터의 첫 외형과 진열대·타일·관제실 장식이 포함된다. 칠판·CCTV는 시각 장식이며 아직 작동하지 않는다. 기존 동작과 임시 물리 충돌 크기는 유지.
